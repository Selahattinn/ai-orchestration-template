# API Design

## Metadata
- status: active
- owner: platform-team
- review_cadence: monthly

## Purpose
Define API resources, contracts, and evolution strategy.

## Use When
- A new service or endpoint set is being designed.
- Existing APIs need contract cleanup or versioning.

## Checklist
- Resource naming is consistent and domain-driven.
- Request/response schemas are explicit.
- Error format and status code mapping are defined.
- Pagination/filtering/sorting behavior is documented.
- Versioning and compatibility strategy is clear.

## Output Contract
- Endpoint inventory
- Payload schema summary
- Error model table
- Open questions list
